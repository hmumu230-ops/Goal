【plan-mode 指令】用户调用了 /plan-mode。流程由 `.devin/plan.md` 的 `status` 字段驱动，只有一道门禁：**批准前全程只读**。

1. **进入即开始**（status=brainstorm）：读代码、提方案、摆观点、给取舍，结论随时沉淀进 plan.md。调研面宽时并行派多个 `subagent_explore` 分片探索（找既有实现/摸相关组件/查测试惯例），方案设计也可派不同视角各出一稿再汇总——**子代理给结论后，关键文件你要亲自复读确认**。只读阶段只允许 `subagent_explore`，写型子代理会被拦。**进入方式三种**：口令、你主动创建 `.devin/plan.md`（frontmatter `status: brainstorm`）、或钩子检测到疑似非平凡实现任务时自动进入（自动进入时用户可随时说「直接做」跳过）。琐碎任务（typo/单行修复/纯问答/纯调研）不要进，也别替自动进入的计划敷衍了事。
2. **提问纪律**：拿不准需求或方案选型时用提问工具当场问，推荐项放第一个标注「(推荐)」；只问方向性问题，次要细节自己假设写进计划。**禁止用提问问「计划行不行/要不要继续」**——写完改 `review` 就是提交评审。
3. **收敛就写**（status=drafting）：讨论收敛后自己把 status 改 `drafting`，按 `%APPDATA%\devin\plan-format.md`（或项目内 `.devin/plan-format.md`）模板把计划**增量**写进 plan.md：预期效果 / 方案与结论 / 具体执行操作 / 风险与备选 / 验收清单。decision-complete：不留"待定/待确认"；只写推荐方案，被否选项一句理由带过。**plan.md 是共享编辑面**——用户可能直接改它，以文件内容为准。
4. **提交评审**（status=review）：写完改 `review` 停下等意见；用户提意见就改，保持 review。
5. **执行**：用户说「执行计划」→ 钩子校验（章节齐全 / 无 ❓与待定 / 有编号步骤）通过后自动生成 `.devin/goal.md` 接力目标模式，旧计划归档 `.devin/plans/`。可附带强度：「执行计划·严格」→ `strict: true` 高强度验收；「执行计划·宽松」→ 放宽拦顶。
6. **可选标准**：用户说「写验收标准」「写测试标准」才补——能机检的 `[check: <命令>]`、只能人看的 `[human]`、都不行无标签自证，汇总进验收清单供执行阶段用。用户没点名的不要写。

参数：`status` → 汇报当前状态；带任务描述 → 直接以该任务进入。**硬性规则：唯一出口是用户说「执行计划」过验收**——`off`/「退出计划模式」/「直接做」等口令只回锁定说明，不再退出；你也不能把 plan.md 的 status 改成 off/done 自救（钩子会恢复为 brainstorm 并记警告）。彻底放弃只能由用户删除 `.devin/plan.md`。

**回合规则**：每轮只能以两种方式结束——向用户提问（先把未决问题标 ❓ 写进 plan.md 再停，钩子会放行），或把 plan.md 更新到当前进度后停下；drafting 中计划不完整且无 ❓ 会被拦回（最多 12 次，确实卡住写 `.devin/blocker.md`）。每第 5 条消息自动重发完整协议。
